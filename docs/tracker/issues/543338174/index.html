[Internal Security Finding] Insecure Webhook Signature Verification in Payments Webhook Handler (/api/v1/payments/webhook)

category Component: Security > Financial & Payments Security > Webhook Ingress
JD
johndoe@company.com (John Doe - Internal Privacy Assurance) reported on October 17, 2026 14:00 UTC
reply more_vert

Executive Summary

During an internal security review of the Payments Platform, Privacy & Security Assurance discovered that the payment callback handler at /api/v1/payments/webhook accepts incoming transaction status notifications without validating the cryptographic HMAC-SHA256 signature passed in the X-Signature HTTP header.

Affected Asset & Endpoint

  • API Endpoint: /api/v1/payments/webhook
  • Code Location: //depot/services/payments/webhook_handler.py

Vulnerability Findings & Impacted Scope

  • X-Signature header is parsed but never cryptographically verified against the shared secret key.
  • transaction_id and status accepted from arbitrary unauthenticated POST callers.
  • payment_amount and settlement_status can be forged to complete orders without actual payment.

Reproduction Request

curl -X POST "https://payments.enterprise.internal/api/v1/payments/webhook" \
  -H "Content-Type: application/json" \
  -d '{"transaction_id": "tx_99214a", "order_id": "ord_8812", "status": "COMPLETED", "amount_paid": 450.00}'

Sample Response / Verification Payload

{
  "status": "ACK",
  "transaction_id": "tx_99214a",
  "message": "Payment confirmed and order ord_8812 marked as settled."
}

Business & Security Impact

Critical financial security risk. An attacker or malicious party can forge arbitrary payment confirmation webhooks to settle unpaid invoices or unlock premium services without completing actual payment gateway transactions.

Proposed Remediation SLO

P1/S1 Financial & Payment Infrastructure Vulnerability: Resolution required within 48 hours of initial triage (Target Due Date: October 23, 2026 18:00 UTC) in accordance with Payment Gateway Security Standards.
